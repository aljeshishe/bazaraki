# Комментарии в коде

- По умолчанию комментариев нет. Хорошие имена и понятный код говорят сами за себя.
- Комментарий добавляется, только когда из кода не очевидно, *почему* сделано так.
- Если комментарий нужен — коротко: одна строка лучше абзаца.
- Не объяснять, что делает код, не пересказывать diff и не ссылаться на текущую задачу/фикс/вызывающий код
  («используется в X», «добавлено для сценария Y»). Это место для сообщения коммита или описания PR, а не для кода.
- Не делать упор на историю изменения: текущее состояние кода говорит само за себя.
- Исключение — юнит-тесты: их можно документировать подробнее, если это помогает понять, как устроен тест и что он проверяет.
