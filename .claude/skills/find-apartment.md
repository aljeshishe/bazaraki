# find-apartment

Подбор квартиры на аренду в Лимассоле из снапшота bazaraki. Работает в `/Users/alekseygrachev/git/bazaraki/`.

## Когда вызывать

Пользователь говорит «подбери квартиру», «найди квартиру в Лимассоле», «обнови подборку», «новый снапшот пришёл — пересмотри», и т. п. Скилл предполагает, что в `output/*.parquet` есть свежие данные.

## Что есть в репозитории

- `output/{YYYY-MM-DD HH:MM:SS} real-estate-to-rent_real-estate-for-sale.parquet` — снапшоты, набираются регулярно.
- `analytics/requirements.md` — **источник истины** по требованиям пользователя (бюджет, КУ, тип, желательное, калибровочные якоря YES/NO).
- `analytics/find_apartment.py` — пайплайн: фильтры → effective price → prelim score → скачивание фото топ-40 → JSON для ревью.
- `analytics/render_report.py` — рендер финального HTML + CSV.
- `analytics/.photo_cache/_anchors/` — кэш фото калибровочных якорей (YES_*, NO_*).
- `analytics/vision_deltas.json` — оценки фото от прошлого запуска.

## Стадии

### 0. Подтвердить вводные

1. Прочитай `analytics/requirements.md` и кратко резюмируй пользователю: бюджет, КУ, типы, желательное, последний список YES/NO якорей.
2. Спроси: «Те же требования или поменялось что-то?» Используй `AskUserQuestion`. Если поменялось — обнови `requirements.md` перед запуском.

### 1. Выбрать снапшот

```
ls -1 output/*.parquet | sort | tail -1
```

Используй самый свежий по дате в имени файла. Если пользователь явно назвал дату — используй её. Запиши выбранный путь и базовую дату (например `2026-05-17`) для имён выходных файлов.

В `find_apartment.py` поправь константу `SNAPSHOT_DATE` (и путь `PARQUET`) под выбранный файл.

### 2. Запустить пайплайн фильтров

```
uv run python analytics/find_apartment.py
```

Должно появиться:
- `analytics/limassol_rentals_all_{DATE}.csv` (≈ 400+ строк после фильтров)
- `analytics/_top40_for_review.json` (топ-40 по prelim score с путями к локальным фото)
- `analytics/.photo_cache/{ad_id}/{0..3}.webp` для каждого топ-40

Если какие-то фото вернули `403` — повтори запрос с заголовком `Referer: <url объявления>` (см. предыдущий запуск). Это бывает для удалённых объявлений.

### 3. Освежить якоря в памяти

Прочитай через Read tool по 2 фото каждого YES/NO якоря из `analytics/.photo_cache/_anchors/`:
- `YES_6410040`, `YES_6464355`, `YES_6408798`, `YES_6448744`
- `NO_6450012`, `NO_6470522`

Если якоря изменились в `requirements.md` — скачай новые через requests с `User-Agent` и `Referer`, и сохрани сюда.

Зафиксируй у себя признаки YES (свежие белые стены, дизайнерские акценты — кресло/картина/ваза, монохром или тёплый минимализм, большие окна) и NO (плитка с орнаментом «ёлочкой» или мозаика 2000-х, тёмная МДФ-кухня старого типа, общий «съёмный-бюджет» вид).

### 4. Визуальный обзор топ-40

Для каждого объявления из `_top40_for_review.json` прочитай 2–4 фото через Read tool (мультимодальный Claude видит картинки напрямую). Сохраняй оценки в словарь:

```
{
  "<ad_id>": {"delta": <float in [-3, +3]>, "comment": "<1–2 фразы по-русски>"}
}
```

Логика дельты:
- Стильная/современная мебель, чисто, новостройка с акцентами → +1.5 ÷ +2.8
- Нейтральный современный без выраженного стиля → 0 ÷ +1
- Только рендеры/экстерьеры без интерьера → -0.3 ÷ -1.0
- Дешёвая «съёмная» эстетика, дешёвые серые диваны, без акцентов → -1.0 ÷ -1.5
- Явно устаревший интерьер (плитка/мебель 90-х/2000-х, тёмная МДФ) → -1.5 ÷ -2.5
- Нет фото в датасете → -2.0

Если есть видимый бассейн/вид на море на фото, которых не было в тексте — это **повышает** дельту, даже если другие признаки слабее. Если на «новостройке» видно совсем нестильную мебель — **снижай**, фото важнее текста.

Записать результат в `analytics/vision_deltas.json` (полностью перезаписать старый файл).

### 5. Рендер финального отчёта

```
uv run python analytics/render_report.py
```

Должно появиться:
- `analytics/limassol_rentals_all_{DATE}.csv` обновлённый (с `vision_delta`, `final_score`)
- `analytics/limassol_rentals_top15_{DATE}.html` — финальная таблица

Открыть в браузере:
```
open analytics/limassol_rentals_top15_{DATE}.html
```

### 6. Сводка пользователю

Кратко в чат:
- Общее число кандидатов после жёстких фильтров.
- Топ-5 ad_id со скорами и причинами.
- Сколько с эффективной ценой ≤ €1600 (под-лимит).

## Правила

- **Все файлы строго внутри `analytics/`.** Не создавай ничего в корне репо, в `/tmp`, в `~/` и т. п. Фото-кэш — `analytics/.photo_cache/`.
- Если `requirements.md` отсутствует или явно устарел (>3 мес назад) — сначала спроси пользователя про предпочтения и пересоздай его.
- При визуальном ревью **доверяй фото больше, чем тексту**. «Modern» в описании ничего не значит, если на фото вторичка из 2000-х.
- Эффективная цена = listed + max(0, КУ − сумма_включённого). КУ по умолчанию €150/мес.
- Сортируй финальную таблицу по `final_score` ↓ без обрезки на 10 (чтобы видеть разницу между топом).
- Если новый снапшот меньше прошлого по числу кандидатов (>20% drop) — упомяни это в сводке, может быть проблема с парсингом.

## Когда НЕ использовать

- Если пользователь просит другие города (Larnaca/Paphos/Nicosia) — нужны другие якоря, перенастрой `find_apartment.py` или запроси новые YES/NO.
- Если данных за нужную дату нет в `output/` — попроси пользователя сначала запустить парсер, не пытайся скачивать с bazaraki напрямую.
- Если требования радикально другие (например покупка, не аренда) — это другая задача, не используй этот скилл.
